# 画面编排原则

这是制作决策指导，不是动画参数教程。具体缓动、回弹和错峰由验证过的模板负责。

## 该不该动

动效服务重点强调、关系解释、状态变化或必要的注意力引导。没有明确作用就不加；不为了动画密度而添加事件。静态阅读和真人表达都是合法选择，不强制每段写多个 beats。

内容与上屏文案准则在 [content-planning.md](content-planning.md) 中定义，内容确认前就应应用。画面规划沿用已确认内容，不在本阶段重新扩写文案。阅读停留取决于真实内容和口播，不设跨场景统一秒数；若排版后仍不可读，回到内容确认调整，不擅自删改。

默认画布是 1920×1080 的 16:9 横屏。输入媒体的比例只影响它在布局区域内的适配方式，不能改变成片比例；仅用户明确指定时使用其他画布。

## 怎样组合布局

按观众任务分配人物和内容空间。观点、清单、标题用白板布局，人物 PIP 居左或居右。录屏能完整铺满时用 `screen-full@1` 隐藏 PIP；录屏需要人物在场时用 `screen-pip-*`，PIP 压在录屏外侧边上。任务变化时才换布局，不为变化而移动 PIP。人物、动效、字幕、来源与关键 UI 不相互干扰。白板内容放在避开 PIP 的安全区。

用户录屏完整等比显示，不裁边或放大。空间不足修改布局；仍不可读时请用户重录或确认其他呈现方式。

成片实现必须直接使用 `StageLayout`，不得根据截图、比例常量或 `computeStageLayout()` 的结果另搭一套 PIP 外框。人物只通过 `presenter` 槽进入布局，由该槽统一提供圆角与裁切。白板上的标题、卡片、图片和动效以布局的 `safe` 矩形为坐标系；整幅 `content` 只承载背景和非关键信息。不能用“看起来没压住人物”代替 safe 区约束。

## 使用模板

先看适用场景和空间需求，再看动态预览；不要只按名称选择。成熟模板按下面的两层模型使用，不临场重新设计弹簧。候选不适用时保持简洁，或提出专项研发需求。

### 模板是动效参考，不是成品画面

每个模板包含两层，处理方式相反：

- **动效本体**：时序表、缓动与逐帧计算、错峰与收尾节奏、DOM 结构。README 的「动效描述」写的就是它，但部分条目会用演示语境的说法（「3」「个方法」「强调色」之类），读的时候换成中性词，别把演示文案当成动效的一部分。这是已验证资产，原样保留，不重写弹簧、不改错峰、不合并或拆分动作。
- **演示语境**：源码里为了独立可看而写死的**演示文案**、根节点**白色纸面背景**、**单个写死的强调色**。这些是占位，不属于动效本体；摘取动效本体时一并抛弃，不要跟着搬进成片工程。

判断方法：看到 `background: "#ffffff"`、`#1d1d1f`、`#8a8a8a` 这类字面色值和模块级演示文案数组（`ROWS`、`STEPS`、`DEFAULT_WORDS` 等），默认读作占位。文件头的 `Demo stage` 注释说明的是它能独立预览，不是叫你去改。

### 用上模板：摘取动效本体

参考模板只读。不要在 `src/motion-library/` 里、更不要在本库的模板文件上做本片适配——改了就拿不到后续更新，也会让“哪些动效已验证”变得不可信。

用法是从模板**摘取动效本体**，落到成片工程 `src/` 下自己的场景组件（与 `src/motion-library/` 分开）：

1. **摘取**：CONFIG 动画参数、时序表与缓动／tween 计算、错峰与收尾节奏、DOM 结构及它依赖的 CSS 布局。原样搬，不重写弹簧、不改错峰、不合并或拆分动作。
2. **替换**：演示文案改由 props 或本段已确认内容提供；根节点不再自持背景，纸面交给 `StageLayout` 和全片背景；写死色映射到 `theme` 角色。
3. **映射**：字 → `theme.text`，次要字 → `theme.mutedText`，纸面 → `theme.surface`，线 → `theme.line`，唯一强调色 → `theme.primary`，实心块上的字 → `themeRoles(theme).onAccent`。
4. **接参**：场景组件接收 `theme`（来自 `resolvePalette(plan.palette)`）和本段内容，签名跟已注入式模板保持一致。

模板已接收 `theme` 和 props 时不必摘取，直接当组件用。

要改模板本身，那是技能开发动作，不是制作动作：先在 `preview/` 实现并人工审阅，通过后才写入 `assets/visual-kit/`。制作过程中不顺手改参考模板。

模板 README 只写适用场景与动效描述，不写接入示例；接入规程以本节为准。

### 配色边界

模板不决定配色。全片仍只选一套已注册 palette，选择规则在 [color-planning.md](color-planning.md)。摘取后的场景组件只消费 theme 角色，不允许引入新 hex，也不为单段单独改 hex；背景换了必须换兼容配色。

这些原则是当前已明确的制作约束，不宣称所有历史审美经验已验证。历史研究的固定人物占比、变化频率和聚焦裁切建议不能直接继承；开发侧后续通过真实样片研究逐项复核，制作时无需加载归档。
