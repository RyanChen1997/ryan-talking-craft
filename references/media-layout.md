# 媒体适配

用户录屏与辅助演示视频：保持全部源画面、原始宽高比，objectFit=contain；禁止 cover、空间 crop、zoom、数字推近、拉伸。可以完整等比缩小到布局区域。

时间剪辑是另一回事：允许源时间片段截取与忠实的独立片段重排。禁止通过重排伪造操作顺序或因果。

比例不匹配时允许有设计意图的留白／matte，不为消除空白裁掉视频。优先给录屏更大区域、缩小或隐藏人物、预留字幕。主口播人物 PIP 单独以人脸与手势安全约束裁切，不能套用到录屏上。

主口播 PIP 必须作为 `StageLayout.presenter` 渲染，不在外部另画人物框。人物媒体填满该槽；可在不切掉脸、手势和必要物体的前提下使用 cover，并保持静音。最终圆角来自布局槽的 `borderRadius` + `overflow: hidden`，不能仅给视频本身设置圆角，也不能依赖源视频四角恰好露出圆角。

截图是否允许局部展示取决于任务与真实性约束；不能将截图的聚焦模板套到受保护视频。分析 ROI 不进入成片。

## 人物 PIP 取景窗

源片宽高比和 PIP 槽的宽高比很少一致。先把代价算清再定窗，不靠目测。

槽的宽高比以布局的 presenter 槽为准（白板变体当前是 4:5）。实现时让视频在槽内自适应（宽度百分比 + 源片 `aspect-ratio`），不写死槽的像素尺寸，也不调用 `computeStageLayout()` 去另搭外框。

源片比槽更竖时，用 cover 填满槽只能保留 `源宽高比 ÷ 槽宽高比` 的高度：9:16 源进 4:5 槽只剩 70.3%，1920 高里要丢掉约 570px。这是算术结果，不是审美选择，写进计划。

定窗三步：

1. **实测人物**。对整条人物素材做一遍 1fps 逐行扫描，取所有帧里最靠上的头顶行和最靠下的必要内容行（手势、手持物），记成源片高度的百分比。这是确定性的像素行扫描，不是看图任务，不占 `video-understanding.md` 的联系表预算；也不要拿 3～6 帧抽样代替——手势会低于静止构图，抽样看不出最坏情况。
2. **留余量**。取景窗上沿定得让最靠上的头顶在窗内距窗顶 ≥ 8% 槽高，且按全片最坏帧核对，头部必须帧帧完整。
3. **对下沿**。取景窗下沿不低于实测必要内容的最低点。两条同时满足，才可以用 cover 填满槽。

取景窗数值只允许来自实测。没测过就写"未测"并把取景窗标为待确认，不要写一个像实测的数。最终取景窗、实测区间与可见高度比例记进 `visual.beats` 或 `qa/production.json`，让复核的人能重算。

## 源片比槽更竖时的取舍

按上节规则能同时装下头顶和手势，就用 cover 填满槽。这是默认方案，不需要额外理由。

满足不了（手势幅度大、必要内容超出窗口），或用户明确要求看到更多身体时，才允许在槽内等比缩小：缩到刚好装下必要内容的最小程度，不为美观多缩；留边用 palette 的 `mediaMatte`，与舞台底色接近，读作"画面窄一点"而不是"加了一圈边"；记录缩放比例、单侧留边占槽宽的比例和可见高度比例。

**禁止在 PIP 内叠加第二层画面去填满槽**：模糊放大的同源画面、铺满的色块、渐变贴图都不行。那会在人物两侧形成一圈光晕，是本库明确不要的效果。单层 `contain` 没有光晕，但人物被压得更小，只在上面两种方案都不可行时才考虑。

缩小后人物明显变小时不要继续缩。宽度占比低于 0.7、或单侧留边超过槽宽 15%，就向上反馈：当前布局没有适配这个源片比例的 PIP 槽，需要新增布局变体或调整槽比例。不得自行改 `computeStageLayout` 的常量，也不得按比例另搭一套 PIP 外框（见 `visual-principles.md`「成片实现必须直接使用 StageLayout」）。

## 常见错误

- 把录屏那条"比例不匹配时允许留白／matte"搬到人物 PIP 上，于是用 `contain` 或垫底来填槽。留白许可只属于录屏；人物这一侧是"填满该槽"。
- 没做全片实测就断定"用 cover 必然切头"，据此退回 `contain`。
- 为了让填满槽的方案成立，把没测过的取景数字当成实测结论写下来。
- 只核对圆角就收工：四角由容器拥有（圆角正确）和头顶未被切掉是两件独立的检查。
