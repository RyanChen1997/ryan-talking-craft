# 分阶段验证

内容阶段：语义忠实、文案精简、时间段有效、素材引用存在、录制需求写清内容和时长。
素材阶段：文件实际存在且可解码、来源可信、用户录屏完整性约束。
画面阶段：输出尺寸与用户要求一致（未指定时为 1920×1080）、布局兼容、文字／字幕／UI 可读且不冲突、完整音轨时长覆盖。
制作阶段：类型检查、帧范围、素材越界、唯一可听音轨、字幕渲染、局部动态播放与边界同步。每种白板 PIP 布局至少抽一帧核对：人物四角确实被布局容器裁切，所有关键文字、卡片和动效都在 `safe` 矩形内。
交付阶段：分辨率、fps、时长、解码、音频与实际观看结果。

v2 使用 project_plan.py validate --visual；旧 validate_design/validate_motion_plan/validate_timeline 只接受旧结构，不直接套到 plan.json。独立媒体检查脚本仍可复用。

通过后写 qa/production.json 或 qa/delivery.json：

```json
{"passed": true, "plan_hash": "project_plan.py hash --visual 的结果", "checks": [{"name": "实际完成的检查", "evidence": "报告或预览路径"}]}
```

passed 必须基于实际运行与观看，不为通过门禁填写。计划哈希只防止旧报告误用，不能证明代码或输出质量；代码或媒体内容变更也必须重新检查并记录文件哈希。缺失真实媒体时明确说明同步与可读性尚未验收。

静态阅读不构成失败，不设置全局固定动画密度、人物占比或审美分数门槛。
