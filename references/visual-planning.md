# 画面方案

内容与素材先确认。选择顺序：信息关系 → 主要载体 → 候选模板 → 兼容布局 → 背景 → 配色 → 对齐口播。

模板、布局、背景与配色索引在 assets/visual-kit/catalog.json，代码入口和 README 一一对应。只选择当前索引中 `status` 为 `reviewed` 的模板和布局，以及已注册的背景／配色；旧组件与未晋级 staging 不在正式库中。按 `carrier` + `informationRelations` 缩小模板候选；布局在白板（`whiteboard-pip-*`）与录屏（`screen-full`、`screen-pip-*`）两组里选，再读对应 README。

候选模板按动效参考使用：动效本体摘取到成片工程自己的场景组件，参考模板只读；演示文案与演示白底属于占位，替换为本段已确认内容与注入的 `theme`。规程见 [visual-principles.md](visual-principles.md)「使用模板」。`reviewed` 表示动效已验收，不表示画面可直接使用。

每段 visual 包含 layout、template（可为 null，表示静态）、beats（简短的口播触发与展开顺序）、clips（媒体源范围）。不为稳定模板重复抄写内部所有动画帧。

全片 `output`、`background` 与 `palette` 写在 plan 顶层，不写在段落里。`output` 未经用户指定时保持初始化的 1920×1080，输入媒体比例不覆盖它。背景负责舞台，配色负责字／卡片／强调／字幕色。选定背景后读取 [color-planning.md](color-planning.md)，用口播联系表在兼容方案中选一套。模板只接收 `theme`，不拥有颜色——这是目标状态，未注入式的模板在摘取后由成片场景组件完成映射（见 `visual-principles.md`「使用模板」）。

预览工程是独立的仓库工具，不随 skill 安装。成片工程需要预览候选时，接入共享源码并只注册相关组件即可，不依赖仓库 preview 路径。配色对照入口：`Palette-Compare`。

录屏只允许时间裁剪；frame range 使用成片帧，source_in/source_out 使用源秒，禁止混淆。完成态要有阅读空间，但不套固定静止上限。

## 画面确认稿的输出格式

画面确认稿有两个去向，内容不一样：

- **文档**（`<spec-dir>/visual-review.md`）：完整记录，含 ID 说明表。供人复核，也供后续 QA 查。
- **发给用户的对话消息**：抬头 + 主表 + 收尾问句。**不发 ID 说明表**——用户要看的是“这一段画什么”，不是 ID 词典。

**① 抬头**

```
*** 画面确认稿 · <片名> ***
`<slug>` · <宽>×<高> · <时长>s · <N> 段
```

再列三行：画幅、背景、配色，都写 catalog id。

**② 主表**

```
| 段落 | 布局 | 模板 | 关键展开顺序 |
```

- 「关键展开顺序」写口播触发点 + 展开顺序，不抄模板内部每一帧。
- 模板为 `null` 时写 `None`，并在该行说明是本段自建还是直接引组件。
- 素材与模板 ID 用段号互指：后面 ID 说明表只列本片实际用到的，不抖完整索引。

**③ ID 说明表**（只进文档，不发对话）

只列本片实际用到的 id，按「布局 → None → 模板」排序：

```
| 类型 | ID | 是什么 |
```

- 「是什么」描述**动效本体**（谁先动、错峰多少、命门在哪），不抄模板 README 原文。README 原文混着演示语境（演示句干、演示数字、演示强调色），那些是占位，抄进确认稿只会让人更糊涂。
- 布局的描述写“区域怎么分、人物在哪一侧、内容排在哪个区”，不写变体名。
- 必须包含 `None` 一行：说明本段没有对应模板，用 safe 坐标 + 公共运动工具自建，不新造弹簧。
- 背景与配色同样是 id。用户没主动问到就不列；一旦列就要写清它管什么（背景管舞台，配色管字／卡片／强调／字幕色）。

**④ 收尾问句**

只问下一步：`可以直接开始搭画面了吗？还是说还有其他的修改？`
